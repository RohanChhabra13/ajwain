# Workboard — Small Business Work Management Platform

**Stack:** Spring Boot 3 (Java 17) · PostgreSQL · React 18 + TypeScript (strict) · Vite.
Implements the **MVP and V2** scope of the product definition. The "Future" list (calendar/email/WhatsApp integrations,
Google/Microsoft sign-in, automation, approvals, time tracking, AI, billing, public API/webhooks) is intentionally not built.

## Run it
```bash
cp .env.example .env            # set DB_PASSWORD and JWT_SECRET
docker compose up --build
# App: http://localhost:3000     API: http://localhost:8080/api
```
Open the app and **sign up**. That creates your user, your organization, and a "General" workspace.
To bring teammates in, go to **Team**, enter their email, and either they are added directly (if they already have an account)
or you get an **invitation link** to send them; they sign up through it and land in your workspace.

### Development
```bash
docker compose up db -d                       # Postgres only
cd backend && mvn spring-boot:run             # API on :8080
cd frontend && npm install && npm run dev     # UI on :5173 (proxies /api to :8080)
cd frontend && npm run typecheck              # TypeScript strict check (also runs as part of `npm run build`)
cd backend && mvn verify                      # unit + integration tests (integration needs Docker)
```

## Design notes
- **Tenant isolation:** every resource resolves to an organization; `AccessService` checks membership on every request.
  Owners/admins see every workspace of their organization; Members only the workspaces they were added to.
- **Statuses** carry a *category* (Not started / In progress / Done). Overdue, dashboards, reports and recurrence use the category, so renaming or adding statuses never breaks them.
- **Notifications** are in-app only. Invitations are links you share yourself (no email sending yet).
- **Schema** is generated by Hibernate (`ddl-auto: update`). Add Flyway migrations before production use.
- **Passwords** are bcrypt-hashed; sessions are stateless JWTs (24 h). There is no password-reset-by-email or email verification yet.

## Deploy frontend + Spring Boot API on Vercel (Container Runtime beta)

The root `vercel.json` uses Vercel Services with the Container Runtime. It routes `/api` and `/api/*` to the Spring Boot service and all other paths to the React frontend. The frontend and backend Dockerfiles are under `frontend/Dockerfile.vercel` and `backend/Dockerfile.vercel`.

1. Push this repository to GitHub and import it into Vercel with the **repository root** as the Root Directory.
2. Ensure the Vercel project/account has access to the **Container Runtime / Services** beta feature. This deployment path is different from a standard static Vite deployment.
3. Create a Neon PostgreSQL database and add these environment variables in Vercel for the backend service (Production, and Preview if needed):
   - `DB_URL` — JDBC URL, e.g. `jdbc:postgresql://<neon-host>/<database>?sslmode=require`
   - `DB_USER` — Neon database username
   - `DB_PASSWORD` — Neon database password
   - `JWT_SECRET` — a random secret of at least 32 characters
   - `CORS_ORIGINS` — your deployed frontend origin, e.g. `https://your-project.vercel.app` (comma-separated origins if needed)
   - `STORAGE_DIR` — optional; defaults to `./data/uploads`
4. Deploy. Check the backend service logs and open `/api/health`; it should return `{"status":"ok"}`.

### Deployment limitations to address before relying on production data

- The current attachment implementation writes files to local disk. Vercel container instances are ephemeral and can scale down, so uploaded attachments are **not durable**. Use persistent object storage (for example, an S3-compatible provider) before relying on attachments in production.
- The current scheduled reminder job runs inside the Spring Boot process. Since Vercel containers scale down when idle, scheduled reminders are not guaranteed to run on schedule. Move this job to a scheduled/queue-based service before relying on reminders.
- Hibernate currently uses `ddl-auto: update`; take a database backup and introduce controlled migrations before production use.
- Vercel's custom Container Runtime / Services feature is currently beta and has its own limits and pricing. Confirm it is enabled for your project before deploying.
